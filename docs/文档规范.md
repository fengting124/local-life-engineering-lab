# 文档规范

- Status: Active
- Type: Reference
- Owners: Project maintainers
- Last verified: 2026-07-12
- Source of truth: `README.md`, `docs/**/*.md`, `scripts/check_docs.py`

本文定义 LocalLife 文档体系的分类、生命周期、写作规则和维护触发条件。它是文档审查和文档 CI 的事实来源。

## 适用读者

- 新增或修改文档的维护者。
- 审查 PR 时需要判断文档是否同步的 reviewer。
- 需要区分当前实现、计划能力和历史记录的读者。

## 文档类型

每篇文档只能有一个主要类型。

| 类型 | 用途 |
| --- | --- |
| `Overview` | 项目概览和入口。 |
| `Tutorial` | 帮助读者按顺序学习完整知识。 |
| `How-to` | 帮助读者完成具体操作。 |
| `Reference` | 接口、配置、数据结构和契约事实。 |
| `Explanation` | 解释架构原因、设计取舍和边界。 |
| `ADR` | 长期有效的架构决策。 |
| `Plan` | 尚未完成的实施计划。 |
| `Interview` | 面试表达、问题和演示材料。 |
| `Historical` | 保留项目演进记录，不再指导当前实现。 |

教程、参考、解释和面试表达混在同一篇时，优先拆分或改成链接。

## 生命周期

正式文档标题下使用以下元数据：

```markdown
- Status: Draft | Active | Superseded | Historical
- Type: Overview | Tutorial | How-to | Reference | Explanation | ADR | Plan | Interview
- Owners: Project maintainers
- Last verified: YYYY-MM-DD
- Source of truth: `相关代码、配置、测试或命令`
- Superseded by: `docs/path.md`
```

规则：

- `Draft`：尚未成为实现基线。
- `Active`：当前有效事实来源。
- `Superseded`：已经被明确的新文档替代。
- `Historical`：记录历史过程，不再约束当前实现。
- README、纯索引页和实施计划可以使用简化元数据。
- 不添加空占位字段。
- 测试数量、覆盖率、性能和评测数字必须写明核验日期、命令和代码基线。
- 无法重新验证的旧数字必须标记为 Historical，或删除当前结论。

## 标准结构

正式持久文档优先采用：

```markdown
# 标题

元数据

一段话说明本文解决什么问题。

## 适用读者

## 当前状态

## 设计或操作详情

## 验证方式

## 已知限制

## 相关文档
```

不需要的章节可以省略。禁止创建空章节。

## 写作规则

1. 中文作为主要文档语言，代码标识符和标准技术名词保留原文。
2. 每段只表达一个核心观点。
3. 使用明确主语和当前时态。
4. 文件、类、方法、接口、表、环境变量和命令使用行内代码。
5. 代码块必须标明语言。
6. 操作步骤使用编号列表。
7. 无顺序事实使用项目列表。
8. 只有比较关系适合时才使用表格。
9. 链接必须使用描述性文字和相对路径。
10. 禁止使用缺少命令、代码或配置证据支撑的乐观结论。
11. 禁止把计划能力写成已实现能力。
12. 禁止把 Mock、演示数据和静态页面写成真实生产能力。
13. 禁止在正式文档中保留个人用户名、个人磁盘绝对路径、私人服务器地址和凭据。
14. 示例路径使用 `${PROJECT_ROOT}`、`${JAVA_HOME}`、`${DATA_DIR}` 等变量。
15. 文档中的安全边界必须与真实代码行为一致。
16. 面试表达与技术事实分开维护。

## 文件命名和目录

- 保留已有稳定路径，避免制造大量失效链接。
- 新增中文持久文档使用清晰中文名称。
- 同一目录需要固定顺序时使用两位数字前缀。
- 实施计划和阶段性设计可以使用 `YYYY-MM-DD-主题.md`。
- ADR 使用 `NNNN-主题.md`。
- 纯面试文档放入 `docs/05-interview/`。
- 已替代历史文档放入 `docs/archive/`。
- 移动文件后必须搜索整个仓库并更新引用。

## 维护触发条件

同一个 PR 发生以下变更时必须更新文档：

- API 请求、响应、状态码或错误行为。
- 数据库表、索引、状态机和迁移脚本。
- Redis Key、MQ Topic、消息结构和重试规则。
- 环境变量、默认值、部署方式和健康检查。
- Agent Graph、工具协议、HITL、Checkpoint 和 Memory 行为。
- RAG 数据源、Embedding、Reranker、阈值和评测指标。
- 权限、身份、租户边界和安全策略。
- 正式能力状态。
- 测试命令、测试数量、覆盖率和质量门禁。
- 架构边界和服务依赖。

代码与 Active 文档发生冲突时，文档检查应失败。

## 证据规则

每项重要结论至少提供一种证据：

- 代码路径。
- 配置路径。
- 数据库迁移。
- 测试路径。
- CI Workflow。
- 可复制执行命令。
- 明确验收标准。

禁止只写“已经完成”“已经支持”“已通过验证”。

## 术语表

| 术语 | 统一写法 |
| --- | --- |
| Java 主服务 | `LocalLife Server` 或 `local-life-server` |
| Java MCP 服务 | `LocalLife Copilot MCP Server` 或 `local-life-copilot` |
| Python Agent 服务 | `copilot-agent-service` 或 `Agent Service` |
| MCP | `MCP`，不要写成 `mcp` 作为概念名 |
| HITL | `HITL`，表示 Human-in-the-loop |
| Checkpoint | `Checkpoint`，表示 LangGraph 执行状态快照 |
| RAG | `RAG`，表示检索增强生成 |
| Evals | `Evals`，表示 Agent 评测 |
| 订单号 | `order_no`，除非代码字段确认为 `order_id` |
| Trace | Java MDC 使用 `traceId`，Python/日志字段使用 `trace_id` |
