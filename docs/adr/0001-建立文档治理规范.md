# ADR-0001：建立文档治理规范

- Status: Accepted
- Type: ADR
- Date: 2026-07-12
- Owners: Project maintainers
- Last verified: 2026-07-12
- Source of truth: 文档规范

## 背景

LocalLife 同时包含传统 Java 后端、Java MCP Server、Python Agent、RAG、HITL、测试门禁和面试材料。历史文档中存在教程、计划、面试表达和当前实现事实混杂的问题。

如果文档不区分当前实现、计划能力和历史内容，后续维护者会把旧计划当作当前事实，或者把目标架构误认为已经上线。

## 决策

项目采用 `docs/文档规范.md` 定义的文档类型、生命周期、证据规则和目录职责。

长期有效的架构取舍使用 ADR 记录。面试表达集中放入 `docs/05-interview/`。历史内容放入 `docs/archive/` 或标记为 `Historical`。

## 影响

- 文档 PR 必须同步更新对应入口和反向链接。
- 当前事实必须能追溯到代码、配置、迁移、测试或命令。
- 文档检查脚本成为 CI 的轻量门禁。

## 备选方案

- 继续保留自由形式文档：成本低，但无法阻止旧事实混入当前实现。
- 立即大规模重命名所有文档：结构更统一，但会制造大量链接失效和 review 噪声。

## 验证

文档检查命令：

```bash
python scripts/check_docs.py
git diff --check
```
